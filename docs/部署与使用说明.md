# my_qmt_trade 部署与使用说明

> 本文覆盖两种部署方式：**原生 Windows 部署**（支持全部模式，含 live 实盘）与
> **Docker 部署**（支持 sim / paper；live 依赖仅 Windows 可用的 xtquant，无法容器化）。
> 项目整体介绍、配置详解见 [`README.md`](../README.md)。

---

## 0. 部署方式怎么选

| 场景 | 推荐方式 | 说明 |
|---|---|---|
| sim / paper 模拟盘、长期挂机 | Docker（或原生均可） | 容器化省心，`restart: unless-stopped` 自动拉起 |
| **live 实盘** | **原生 Windows** | xtquant/QMT 网关仅 Windows；容器内无法连 QMT |
| 本地开发调试 | 原生 + `npm run dev` | 前端热更新（5073 代理到 7099） |

**关键认知**：后端进程（`uvicorn server.main:app`）**同时承担常驻调度器**——
进程必须保持运行，盘前选股/研判/下单等定时任务才会触发；启动时还会自动补跑当日已错过的任务。

## 1. 原生 Windows 部署（推荐，支持 live）

### 1.1 环境准备

| 组件 | 版本 | 用途 |
|---|---|---|
| Python | 3.11+ | 后端 + 调度器 |
| Node.js | 18+（推荐 20） | 构建前端 WebUI |
| QMT 客户端 | 券商版（仅 live） | 提供 xtquant 网关（默认路径 `F:\qmt\dg_qmt\userdata_mini`）根据自己实际安装路径修改 |

```bash
# Python 依赖
pip install -r requirements.txt

# 前端构建（产物 webui/dist，由后端同源托管，无需单独起前端服务）
cd webui
npm install
npm run build
cd ..
```

### 1.2 敏感配置 `config/.env`（不入库，需自建）

```dotenv
# ---------- LLM（不填则自动退回 MockLLM，系统照常跑） ----------
DEEPSEEK_API_KEY=sk-xxxxxxxx
DASHSCOPE_API_KEY=sk-xxxxxxxx

# ---------- 行情数据源 ----------
TUSHARE_TOKEN=your_tushare_token

# ---------- 实盘（仅 live 需要） ----------
QMT_ACCOUNT_ID=88888888

# ---------- 通知（可选） ----------
WECOM_WEBHOOK=https://qyapi.weixin.qq.com/...
```

> 变量名需与 `config/llm.yaml` 各 provider 的 `api_key_env` 一致。详见 README §3。

### 1.3 启动后端

```bash
# 方式 A：后台常驻（推荐），日志 logs/backend.log
./scripts/start_backend.sh

# 方式 B：前台调试（Ctrl+C 停止）
./scripts/start_backend.sh --fg
```

就绪后访问 **http://127.0.0.1:7099**（WebUI + API 同端口），API 文档在 `/docs`。

### 1.4 看门狗 + 开机自启（长期挂机建议开启）

```bash
# 看门狗：每 30s 健康检查，后端掉线约 1 分钟内自动拉起（单实例保护）
bash scripts/watchdog_backend.sh

# 开机自启：把 scripts/autostart_backend.bat 复制到 Windows 启动文件夹
#   win+R → shell:startup → 粘贴快捷方式/文件
```

### 1.5 live 实盘启动清单

1. 本机安装并登录 QMT 客户端（mini 模式），确认 `settings.yaml` 的
   `execution.qmt.path` 指向其 `userdata_mini` 目录（也可用环境变量
   `QMT_MINI_PATH` 覆盖，**该环境变量优先**）。
2. `config/.env` 中配置 `QMT_ACCOUNT_ID`。
3. **先用 paper 验证**：WebUI 切到 paper 模式确认选股/计划链路正常。
4. 切换 live：WebUI 实盘页操作，或 CLI `python -m qmt_trade --mode live run`。
5. live 装配失败（QMT 未连接等）会**直接拉闸报错，绝不降级用假数据**——这是设计红线。

> **模式说明**：`sim` = Mock 数据 + 模拟撮合（开发自测）；`paper` = 真实行情 +
> 模拟撮合（真数据模拟盘）；`live` = 真实行情 + QMT 网关（**实盘真金白银**）。
> 三者共用同一套决策/风控/执行代码，且选股、研判等**决策产物跨模式共享**
> （统一存 `data/trade.db`），账本（持仓/订单/资金）按模式隔离
> （live 单独用 `data/trade_live.db`）。

### 1.6 CLI 常用命令（不走 WebUI 时）

```bash
python -m qmt_trade --mode sim run --plan-only        # 看调度日程，验证装配
python -m qmt_trade --mode paper run --once selection # 单跑选股任务
python -m qmt_trade --mode sim backtest --start 2025-01-01 --end 2025-06-30
python -m qmt_trade --mode paper killswitch --status  # 总开关状态
python -m qmt_trade --mode paper reconcile            # 盘后对账
```

## 2. Docker 部署（sim / paper）

### 2.1 构建与启动

```bash
# 一键构建并后台启动（含前端构建）
docker compose up -d --build

# 查看日志 / 状态
docker compose logs -f
docker compose ps
```

访问 **http://localhost:7099** 即可。

### 2.2 不用 compose 的等价命令

```bash
docker build -t qmt-trade .
docker run -d --name qmt-trade \
  -p 7099:7099 \
  -v "$PWD/data:/app/data" \
  -v "$PWD/logs:/app/logs" \
  -v "$PWD/reports:/app/reports" \
  --env-file config/.env \
  --restart unless-stopped \
  qmt-trade
```

### 2.3 数据持久化（重要）

| 容器路径 | 挂载到 | 内容 |
|---|---|---|
| `/app/data` | `./data` | SQLite 账本（trade.db/trade_live.db）、LLM 缓存、Parquet 行情缓存 |
| `/app/logs` | `./logs` | 后端/调度日志 |
| `/app/reports` | `./reports` | 日报/周报 |

不挂载 volume 则容器重建后**账本全部丢失**。备份时直接拷贝宿主 `data/` 目录
（SQLite 为 WAL 模式，建议先 `docker compose stop` 再拷，或用 sqlite `.backup`）。

### 2.4 密钥注入

两种方式任选（**密钥不进镜像**，`.dockerignore` 已排除 `config/.env`）：

1. 项目根目录放 `.env`（格式同 `config/.env`），compose 的 `env_file` 自动注入；
2. `docker run --env-file config/.env ...` 直接注入。

### 2.5 日常运维

```bash
docker compose stop          # 停止（数据保留）
docker compose start         # 再次启动
docker compose restart       # 改代码后快速重启
docker compose up -d --build # 代码/依赖变更后重建镜像并热替换
docker compose down          # 删容器（volume 挂载的 data/logs 不受影响）
```

镜像已内置 HEALTHCHECK（每 30s 打 `/api/health`），配合 `restart: unless-stopped`
宿主机重启后容器自动恢复，调度器启动时自动补跑当日错过的任务。

### 2.6 live 模式与 Docker 的关系

xtquant 是 QMT 随客户端分发的 **Windows 专属库**，Linux 容器无法加载，
因此 **live 实盘不能跑在 Docker 里**。常见组合：

- Docker 跑 paper（7×24 挂机验证策略）；
- live 在装有 QMT 客户端的 Windows 机器上原生运行（§1）。
- 两者的决策产物库（trade.db）结构一致，迁移时只需同步 `data/` 目录。

## 3. WebUI 使用说明

访问 http://localhost:7099（Docker 或原生相同），主要页面：

| 页面 | 功能 |
|---|---|
| 概览 | 账户快照、KillSwitch 档位、当日任务执行状态、调度日程 |
| 选股 | 一键选股（全市场漏斗）、研判精选、观察池；盘前由调度器自动产出 |
| 实盘 | live 模式的持仓/委托/计划与下单执行 |
| 回测 | 历史区间回测（与实盘同一执行链路） |
| 风控 | 三闸门事件、KillSwitch 操作 |
| 设置 | settings.yaml / llm.yaml 在线编辑、数据源健康度 |

**日常节奏**（默认日程见 `config/settings.yaml` 的 `scheduler.jobs`）：

```
06:30 data_sync 数据同步体检 → 07:00 regime 市场状态
→ 08:00 selection 盘前选股 → 08:30 research LLM 研判精选
→ 09:15 plan 生成交易计划 → 09:25 auction_check 集合竞价
→ 盘中 intraday 守护 → 15:30 reconcile 对账 → 16:00 review 复盘
```

错过时段开机不用慌：后端启动时自动按依赖顺序补跑当日已错过的任务。

## 4. 升级与故障排查

### 4.1 代码升级后必须重启后端

改了 `qmt_trade/`、`server/` 代码后：

```bash
# 原生
./scripts/start_backend.sh        # 脚本会自动杀掉占用 7099 的旧进程再起
# Docker
docker compose up -d --build
```

### 4.2 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| WebUI 打开是 JSON 而非页面 | `webui/dist` 未构建：`cd webui && npm run build` 后重启后端 |
| live 页选股/计划为空 | 检查后端是否刚重启过、常驻调度器日志；决策产物在共享 `data/trade.db`，paper 跑过的结果 live 直接可见 |
| 端口 7099 被占用 | `start_backend.sh` 会自动 taskkill 旧进程；手动：`netstat -ano | findstr :7099` |
| LLM 相关功能全部走 Mock | 未配置 API Key（属正常降级 P5）；检查 `config/.env` 与 `llm.yaml` 的 `api_key_env` 是否一致 |
| 当日成本超限后 LLM 停用 | 预算熔断生效（默认 ¥30/日）；调 `llm.yaml` 的 `budget.daily_cny` 或次日自动恢复 |
| 时间不对导致调度异常 | 确认时区为 Asia/Shanghai（Docker 镜像已内置 `TZ=Asia/Shanghai`） |
| QMT 连接失败 | 确认 QMT 客户端已登录 mini 模式；`QMT_MINI_PATH` 环境变量优先于 settings.yaml 路径 |

### 4.3 紧急制动（任何模式下都有效）

```bash
python -m qmt_trade --mode live killswitch --engage "人工避险"   # 停止开新仓
python -m qmt_trade --mode live killswitch --flatten "紧急平仓"  # 全部平仓
python -m qmt_trade --mode live killswitch --reset               # 恢复
```

或在 WebUI 风控页操作。档位持久化在 `system_state` 表，**重启不丢**。
